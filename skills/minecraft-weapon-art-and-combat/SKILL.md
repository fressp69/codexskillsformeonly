# Minecraft weapon art and combat

## Workflow and delivery
- Inspect the latest actual source, approved resource pack, model IDs, user-edited Blockbench assets and gameplay decisions first. Latest user approval wins. Do not recreate approved textures or silently replace working mechanics.
- For finished weapon art deliver editable self-contained **.bbmodel only**; do not deliver PNG sheets, GIF previews or ZIPs as substitutes unless explicitly requested. Embedded textures must open without absolute local paths. Resource-pack export for integration is a distinct engineering task, not a finished art deliverable.
- Read actual model format, UVs, texture dimensions, frame metadata, display transforms and element rotations; preserve user touch-ups. A project's logical UV resolution is not necessarily its texture pixel resolution. Never blindly rescale UVs when the embedded texture has a different pixel size.
- Use native pixel art, hard edges, nearest-neighbor resampling and transparent background. Select canvas based on silhouette/detail: 16x16 for vanilla-simple items; 32x32 for knives, daggers and medium-detail swords; 64x64 for complex railguns, intricate weapons and multi-stage energy overlays; 128x128 only with explicit art direction requiring it. These are starting recommendations, not universal constraints. Do not increase resolution merely for more pixels. Keep the approved resolution once chosen.
- Keep immutable base silhouette and separate editable energy, glow, muzzle flash, recoil and other effect layers during production. Only intended pixels should animate. An aura traveling along a blade must disappear behind its front, not accumulate or animate the blade underneath. If the source is flattened, preserve it exactly and do not falsely claim editable layers exist.
- Animated vertical texture sheets use equal square frames; width W, height W*N. Check divisibility, frame order, alpha, no clipping and exact frame count. A 32x256 sheet has eight 32x32 frames, not a 32x256 per-frame image. Test a full loop and individual frames. First frame can be aura-free if specified.
- Verify in Blockbench: correct display slots (first/third person left/right, GUI, ground, fixed), actual texture visibility and frame order, no unintended rotation or silhouette movement. For black flickering surfaces investigate coplanar faces/z-fighting, duplicate elements, UV bleed and alpha before altering approved art. Tiny intentional separation or removal of redundant faces can resolve z-fighting; verify front and side.
- Separate model geometry rotation, display-slot transformation and texture animation. Never rotate the entire base merely to animate an overlay. For a held weapon preserve approved hand pivot and orientation. Validate exported item model IDs against the actual pack.

## Paper 1.21.11 / Java 21 implementation
- Reuse existing controllers, damage/trust/protection paths, item serial ledger, cooldowns and FX scheduler. Inspect actual signatures rather than guessing. No unrelated changes. Match input event cancellation, charge state, native cooldown group, PDC identity, transfer/restart and shutdown semantics. Preview items must be inert.
- Use physical BlockDisplays for solid luminous beams and mechanical parts; particles supplement geometry, never replace required physical core. Display entities are not real terrain blocks and are not block entities. Use real world blocks for persistent walkable monuments; BlockDisplays for moving decorations, visual-only debris and beams. Tile/block entities such as containers have state and inventories; do not erase them or restore only their BlockData.
- Use a shared muzzle/anchor with neutral entity yaw/pitch. Define immutable local rest geometry about a common axis. For each part with center (cx,cz), scale (sx,sy,sz) along local +Y, translation before rotation is (cx-sx/2,0,cz-sz/2). Let A align local +Y to the normalized shot direction with a stable roll reference. Q=A*rotateY(roll). Set translation=Q*localOffset, left rotation=Q, scale local, right rotation identity. Rotate offsets AND orientation, not each part about its own corner. Use quaternion sign continuity and a stable basis at near-vertical/vertical/downward directions; test every direction. Never double-apply entity yaw. Avoid cumulative transform drift. Initialize display transform in spawn callback to prevent one-frame cubes; use interpolation only after verifying client behavior.
- Holy Lance reference geometry: central square prism plus four short fins near muzzle, each a thin plate at +/- half-width on X/Z; brightness (15,15), gravity false, invulnerable, nonpersistent. At tick t=1..12: grow=min(1,t/2); fade=t<=7?1:max(0,(12-t)/5); width=max(.08,grow*fade); length=(1+31*grow)*max(.15,fade); roll=pi*min(1,t/8); finLength=(t<=1?1.5:t<=10?1.5-(t-1)/9:.5)*fade. Adapt length to resolved shot distance rather than hardcoding 32; width to agreed envelope. For Linebreaker use white-hot core with crimson accents. Sustained ultimate needs its own bounded lifetime and continuous axial spin rather than repeatedly spawning flash beams.
- Separate visual envelope from authoritative collision. Freeze shot origin/direction at release when required. Ray trace/sweep actual geometry, cap range, avoid hitting behind blockers or through protected terrain. Use a swept segment vs entity bounding boxes, deterministic distance ordering and per-cast UUID hit deduplication. Do not apply repeated damage simply because VFX persists. For circular terrain tunnels test distance to finite segment, not axis-aligned cubes; support diagonal and vertical directions and bound all operations. Do not confuse hearts with health points (1 heart = 2 HP).
- Synchronize animation by authoritative cast age, not global animated-texture clocks. Use explicit frame model IDs for one-shot states and native bow use-duration selection where practical; avoid mutating active ItemStacks each tick. A 20-frame sheet at 4 ticks/frame = 80 ticks; 20 at 1 = 20; 30 at 2 = 60. Validate actual edited assets rather than assuming metadata. Use a dedicated item cooldown group if the target API supports it; don't disable ordinary bows. Cooldowns and weapon ownership cannot reset via drop, trade, logout or restart.
- Sound design: escalating charge, a deliberate final cue, layered discharge and tail; use spatial sound, rate limits and sensible volume/pitch. Distinguish Mini/Full/Breach/Ultimate by scale and intensity, not particle spam. Schedule bounded work and remove all displays/tasks on expiry, invalidation, chunk unload and disable.

## Terrain and recovery
- Use protection checks on every affected block, respect world bounds and unloaded chunks, skip tile/block entities, containers, protected structures and unsupported states. Never bypass existing protection by using a display or setting blocks directly.
- Journal exact original BlockData and world/coordinates plus expiry BEFORE mutation; durable atomic persistence, deduplicate overlaps, retain first original, do not overwrite player changes when restoring. Reserve positions transactionally; rollback or fail closed if write fails. Restore overdue entries at startup and on chunk load without force-loading a world. Keep journal until verified restore. No collectible drops, no physics cascade or uncontrolled explosions. Use visual-only debris with cancel-drop/no damage and cleanup. Permanent destruction only for explicitly approved exceptions; cap exceptional blocks per cast and never treat protected bedrock as eligible. Temporary destruction and restoration delay are gameplay parameters, not generic defaults.
- Test no ghost displays, no duplicate damage, no permanent temporary holes after restart/unload, no container loss, no unintended block drops, no trust/protection regressions and no ordinary-item cooldown. Test flat, diagonal, vertical and short shots. Compile against the real project wrapper; report actual tests and client checks separately.
- If exact approved source, recipe, cooldown or pack is missing, state the gap; implement safely isolated pieces instead of inventing finalized values or rebuilding missing production systems. Never claim untested code works in-game.
